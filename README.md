# Переговорка — бронирование переговорной комнаты

Интерфейс бронирования одной переговорной на рабочий день 09:00–18:00: календарь (месяц / неделя / день),
создание, редактирование и удаление броней, корректная обработка серверных конфликтов.

- **Демо:** _ссылка будет добавлена после деплоя_
- **Стек:** Next.js 16 (App Router), React 19, TypeScript (strict), TanStack Query v5, react-hook-form + zod,
  Tailwind v4 + shadcn/ui (Base UI), Vitest + Testing Library, Playwright + axe.

## Быстрый старт

```bash
pnpm install
cp .env.example .env.local
pnpm dev                      # http://localhost:3000
```

| Команда | Что делает |
|---|---|
| `pnpm test` / `pnpm test:coverage` | unit- и компонентные тесты (Vitest) |
| `pnpm exec playwright install chromium && pnpm e2e` | e2e на desktop и mobile, включая a11y-скан (собирает прод-сборку сама) |
| `pnpm lint` / `pnpm typecheck` | ESLint, TypeScript |
| `pnpm build && pnpm start:standalone` | прод-сборка (`output: standalone`) |
| `docker compose -f deploy/compose.yml -p booking up -d --build` | прод в Docker |

Переменные окружения (`.env.example`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `NEXT_PUBLIC_ROOM_TIME_ZONE` | `Asia/Bishkek` | часовой пояс комнаты: «сегодня» и «прошлое» считаются в нём и на клиенте, и на сервере |
| `NEXT_PUBLIC_DEMO_TOOLS` | `false` | демо-инструменты: «занять слот за коллегу» (воспроизводит 409) и сброс данных |
| `DEMO_LATENCY_MS` | — | искусственная задержка API, например `300-800`, чтобы были видны состояния загрузки |

## Что сделано

**Функциональность**
- Выбор даты: виды «Месяц», «Неделя», «День», переход по периодам, «Сегодня», дата в URL (`?view=week&date=…`).
- Просмотр броней дня: блоки в сетке времени, чипы в месяце, на телефоне — списки.
- Создание: протянуть мышью по свободному времени (шаг 15 мин), тап на телефоне, Enter по свободному окну
  с клавиатуры, кнопка «Новая бронь». Форма в один шаг: название, дата, начало, конец
  (в списке конца сразу видна длительность, недопустимые варианты не предлагаются).
- Редактирование и удаление — из карточки брони; удаление с подтверждением.
- Поверхности: поповер рядом с выделением/ячейкой, правый drawer для «Новой брони», нижний drawer на телефоне.

**Бизнес-правила** — одна функция `validateBooking` (`src/domain/rules.ts`) работает и в форме, и в API,
поэтому UI и сервер не расходятся.

| # | Правило | Где |
|---|---|---|
| 1 | В пределах 09:00–18:00 | `checkRange`, `BOOKING_RULES` |
| 2 | start < end | `START_NOT_BEFORE_END` |
| 3–4 | 30 мин – 2 ч | `TOO_SHORT`, `TOO_LONG`; UI не предлагает длительности вне диапазона |
| 5 | Без пересечений, касание границ допустимо | полуинтервалы `[start, end)` в `overlap.ts` |
| 6 | Нельзя в прошлое | `checkTimeline`; сервер берёт «сейчас» из своих часов, клиенту не доверяет |
| 7 | Редактирование не конфликтует само с собой | `findConflicts(…, original.id)` |
| 8 | Сервер может вернуть 409 | см. ниже |

**Конфликт 409 (правило 8).** Форма остаётся открытой, введённое (включая название) сохраняется,
показывается баннер с тем, с чем пересеклось («11:00–12:00 «Коллега»»), расписание обновляется
(инвалидация запросов после любой мутации), предлагается ближайшее свободное окно той же длительности
одной кнопкой. Проверено e2e настоящей гонкой двух браузеров. Воспроизвести руками: включить
`NEXT_PUBLIC_DEMO_TOOLS=true` и нажать в форме «Демо: занять это время за коллегу».

**Другие серверные ошибки**
- 422 (нарушено правило) — сообщение рядом с полем времени или названия.
- 404 при редактировании (бронь удалили) — «Создать как новую» с теми же данными.
- Сеть / таймаут / 5xx — понятный текст и «Повторить». Если запрос на создание упал по таймауту,
  но бронь на сервере успела создаться, повтор распознаёт её как свою, а не как конфликт.

**Состояния UI:** скелетон загрузки, ошибка первой загрузки вместо «пустой» сетки, предупреждение
при неудачном фоновом обновлении, явное пустое состояние дня, спиннер и блокировка кнопки при отправке.

**Адаптивность и доступность:** отдельные раскладки для телефона (списки, нижний drawer, FAB, свайп),
вся навигация и создание доступны с клавиатуры, подписи и `aria-*` у контролов, контраст WCAG AA,
`prefers-reduced-motion`. axe-скан всех видов и открытой формы входит в e2e.

## Допущения

В ТЗ эти места неоднозначны. Вопросы отправлены проверяющему 7 октября; до ответа приняты значения ниже,
каждое меняется в одном месте.

| Вопрос | Принято | Где поменять |
|---|---|---|
| Чей часовой пояс определяет «сегодня» и «прошлое»? | Фиксированный пояс комнаты (`Asia/Bishkek`) для клиента и сервера | `NEXT_PUBLIC_ROOM_TIME_ZONE` |
| Можно ли 09:07–09:41? | Шаг 15 минут | `BOOKING_RULES.stepMinutes` |
| Сегодня 13:20 — можно ли начать в 13:30? | Да: начало ≥ «сейчас», в UI округляется вверх до шага | `checkTimeline` |
| Можно ли менять уже идущую встречу? | Только конец (и название), конец позже «сейчас» | `checkTimeline` |
| Можно ли менять/удалять завершённые? | Нет, только просмотр | `checkTimeline`, `handlers.remove` |
| Длина названия? | До 100 символов, пробелы по краям обрезаются, пустое = без названия | `BOOKING_RULES.titleMaxLength` |

## API

Контракт из ТЗ реализован в `src/app/api/bookings/**` (тонкие Route Handlers) поверх независимых от Next
обработчиков `src/server/handlers.ts` и in-memory репозитория.

| Запрос | Успех | Ошибки |
|---|---|---|
| `GET /api/bookings?date=YYYY-MM-DD` | `200 Booking[]` | `400` |
| `GET /api/bookings?from=…&to=…` *(доп., для календаря, ≤ 62 дней)* | `200 Booking[]` | `400` |
| `POST /api/bookings` | `201 Booking` | `400`, `409`, `422` |
| `PATCH /api/bookings/:id` | `200 Booking` | `400`, `404`, `409`, `422` |
| `DELETE /api/bookings/:id` | `204` | `404`, `422` (завершённая бронь) |

**Отличия от формулировки ТЗ — осознанные:** `409` — только пересечение; нарушение остальных правил — `422`
(данные валидны по форме, но нарушают правило); кривой запрос — `400`. Так клиент различает
«занято, выберите другое время» и «исправьте поле». Ошибки в едином формате:

```json
{ "error": { "code": "CONFLICT", "message": "…", "fields": { "start": "CONFLICT" }, "conflicts": [ /* Booking[] */ ] } }
```

Проверка «пересечение → запись» выполняется синхронно в одном тике, поэтому в одном Node-процессе
две одновременные записи не займут один слот (для БД нужна транзакция или exclusion-констрейнт).
Данные в памяти: перезапуск сервера сбрасывает их к демо-набору. Поэтому нужен один долгоживущий процесс
(Docker / VPS), а не serverless.

**Замена на реальный API:** UI зависит только от интерфейса `BookingsApi` (`src/lib/api/bookings-api.ts`),
который передаётся через провайдер; достаточно другой реализации или `baseUrl`.

## Структура

```
src/
  domain/        чистые правила и расчёты: rules, overlap, schedule, selection, calendar, time
  contracts/     zod-схемы запросов и ответов, общие для сервера и клиента
  server/        обработчики API, маппинг ошибок, in-memory репозиторий, seed
  app/api/       тонкие Route Handlers
  lib/api/       HTTP-клиент: таймаут, отмена, ApiError, проверка ответов
  features/bookings/
    api/         ключи запросов, queries, мутации с инвалидацией
    form/        контроллер формы, схема, разбор серверных ошибок
    composer/    форма брони и поверхности (поповер / drawer)
    components/  экран, тулбар, месяц, сетка времени, списки
  components/ui/ примитивы UI-кита (shadcn)
e2e/             Playwright: CRUD, гонка 409, drag, a11y
```

## Тесты

- **218 unit/компонентных тестов**, покрытие ~88% строк: правила и граничные случаи, геометрия выделения,
  API-обработчики со всеми кодами, HTTP-клиент (MSW), форма (409/404/422/сеть/таймаут), виды календаря.
- **e2e (Playwright, desktop + mobile):** создание → редактирование → удаление, прошедшие даты,
  **реальная гонка двух пользователей с 409**, drag мышью, смена даты в поповере, axe-скан.

## Что не сделано / что бы сделал дальше

- **Хранение** — только в памяти; следующий шаг — БД с exclusion-констрейнтом на пересечение.
- **Защита публичного демо:** лимит размера тела, rate limit и горизонт дат (сейчас in-memory store
  можно раздуть бронями на далёкие даты), security-заголовки в Caddy.
- **a11y сетки месяца:** роли `grid/gridcell` без навигации стрелками — честнее заменить на список
  или реализовать roving tabindex.
- **История браузера:** выбор дня на телефоне делает `pushState`; для выбора внутри вида лучше `replaceState`.
- **Фокус** после закрытия панели возвращается не всегда туда, откуда открыли.
- Точек «есть брони» на днях мини-календаря нет (нужен запрос по диапазону и там).
